# Блок 2. Основы A/B тестирования

Теперь превращаем статистику в рабочий инструмент продуктовых решений.

---

## Модуль 2.1. Что такое A/B тест и причинность

**Цели:** понять, зачем вообще эксперименты и что они дают, чего не даёт аналитика.

**Темы**
- Корреляция ≠ причинность. Почему наблюдательные данные обманывают (confounders).
- Рандомизированный контролируемый эксперимент (RCT) как «золотой стандарт» причинности.
- Контроль (A) и вариант (B). Что значит «при прочих равных» и почему рандомизация это обеспечивает.
- Потенциальные исходы (Rubin causal model) — интуиция: мы никогда не видим оба исхода у одного юзера.

**Что уметь**
- Объяснить, почему «выкатили фичу, метрика выросла» ≠ фича помогла.
- Сформулировать эксперимент для конкретной продуктовой гипотезы.

---

## Модуль 2.2. Метрики и OEC

**Цели:** выбирать правильные метрики — половина успеха эксперимента.

**Темы**
- **Primary (целевая)** метрика — то, ради чего тест. Одна, заранее.
- **Secondary** — помогают объяснить эффект.
- **Guardrail (ограждающие)** — не должны просесть (latency, retention, отписки, краши).
- **OEC** (Overall Evaluation Criterion) — комбинированный критерий успеха.
- Свойства хорошей метрики: чувствительность, измеримость, связь с долгосрочной ценностью.
- Ловушка суррогатных метрик: клики ≠ удовлетворённость.
- Ratio-метрики (CTR = клики/показы) и почему у них хитрая дисперсия (см. дельта-метод, Блок 4).

**Что уметь**
- Для гипотезы «новая кнопка checkout» выписать primary + 2 secondary + 2 guardrail.

**Практика.** Возьмите знакомый продукт, спроектируйте набор метрик для 3 разных фич. Обоснуйте выбор primary.

## Модуль 2.3. Дизайн эксперимента и рандомизация

**Цели:** правильно раздать пользователей по группам.

**Темы**
- **Единица рандомизации:** пользователь, сессия, устройство, кластер. Почему обычно — пользователь.
- Хеширование ID + соль для стабильного и равномерного распределения.
- Стабильность назначения (юзер не должен прыгать между группами).
- Доля трафика (ramp-up: 1% → 5% → 50%), holdout-группы.
- Единица рандомизации vs единица анализа — должны совпадать, иначе ломается независимость.

**Что уметь**
- Объяснить, почему рандомизация по сессии искажает метрики уровня пользователя.
- Реализовать назначение группы через хеш-функцию.

## Модуль 2.4. Размер выборки, MDE и мощность

**Цели:** считать, сколько нужно данных, **до** запуска. Пропуск = слитый эксперимент.

**Темы**
- **MDE** (Minimum Detectable Effect) — минимальный эффект, который хотим ловить.
- Формула размера выборки для сравнения двух средних/долей.
- Влияние на n: базовая конверсия, MDE, α, желаемая мощность (обычно 80%), дисперсия метрики.
- Длительность теста: n / трафик в день, но не короче полного недельного цикла (day-of-week эффект).
- Trade-off: меньше MDE → квадратично больше выборка.

**Что уметь**
- Посчитать нужное n для конверсии 5% → 5.5% при α=0.05, power=0.8.
- Оценить, сколько недель крутить тест при известном трафике.

**Практика.** `statsmodels`:
```python
from statsmodels.stats.power import NormalIndPower
from statsmodels.stats.proportion import proportion_effectsize
es = proportion_effectsize(0.05, 0.055)
n = NormalIndPower().solve_power(effect_size=es, alpha=0.05, power=0.8, alternative='two-sided')
print(n)  # на группу
```
Постройте график: как n зависит от MDE. Прочувствуйте квадратичный рост.

## Модуль 2.5. Статистические критерии

**Цели:** выбирать и применять правильный тест под тип метрики.

**Темы**
- **Двухвыборочный t-тест (Welch)** — сравнение средних (выручка, время). Welch по умолчанию (не требует равных дисперсий).
- **z-тест для долей / χ²** — сравнение конверсий.
- **Mann–Whitney U** — непараметрика, когда распределение дикое, а n небольшое.
- Предпосылки тестов и что делать при их нарушении (тяжёлые хвосты → ЦПТ спасает при большом n, либо трансформация/бутстрап).
- Односторонний vs двусторонний — по умолчанию двусторонний.

**Что уметь**
- По метрике выбрать критерий: конверсия → z/χ², ARPU → t-тест Welch, медиана → bootstrap/Mann–Whitney.
- Прочитать вывод `scipy.stats` и не перепутать statistic с p-value.

**Практика.** Реализуйте руками z-тест для двух долей (посчитайте pooled SE, z, p) и сверьте
с `statsmodels.stats.proportion.proportions_ztest`.

## Модуль 2.6. Анализ и интерпретация результатов

**Цели:** делать выводы, а не просто смотреть «p<0.05».

**Темы**
- Оценка эффекта (absolute lift, relative lift) + **доверительный интервал для эффекта** — важнее самого p-value.
- Практическая значимость vs статистическая. Значимо, но крошечно = не внедряем.
- Что значит «нет значимости»: не «эффекта нет», а «не обнаружили» (вспомнить мощность).
- Решение: раскатывать / откатывать / доитерировать. Учёт guardrail-метрик.
- Как честно отчитаться о результате (эффект, CI, метрики-стражи, оговорки).

**Что уметь**
- Построить CI для разницы конверсий и сформулировать бизнес-вывод.
- Отличить «незначимо из-за отсутствия эффекта» от «незначимо из-за малой мощности».

**Практика.** По результату теста напишите короткий «readout»: эффект, CI, guardrails, рекомендация.
